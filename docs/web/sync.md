# 웹판 2단계 B — 설치판 ↔ 클라우드 자료 동기화 (구현함)

설치판의 큐시트 · 찬양 · 템플릿 · 테마 · 교회 공통 설정을 클라우드 D1 문서([`data-api.md`](data-api.md))와 맞추고,
거기 쓰인 그림 · 영상을 2C 저장소([`assets-api.md`](assets-api.md))에 올린다. **기본 꺼짐.**

코드: `crates/wp-core/src/cloudsync.rs` (엔진 · 문서 모양 · 파일 주소 · 스레드) · `cloudsync/api.rs` (HTTP) · `cloudsync/tests.rs` (단위 시험 · 끝에서 끝) ·
`crates/wp-app/src/cloudsync_ui.rs` (클라우드 연결 창 안 '자료 동기화' 구획). 기존 파일은 등록 줄만: `lib.rs` · `server.rs`(init) · `cloud.rs` 4줄 · wp-app `main.rs` · `cloud_ui.rs` 1줄.
시험 도구: `cloud/test/sync-e2e/run.mjs`.

## 1. 켜기

- '클라우드 연결'(1단계 `cloud.rs`) 의 주소 · 연결 열쇠 · 켜기를 그대로 쓰고 설정 `cloud.sync`(기본 `false`) 하나만 더했다. 둘 다 켜져 있고 주소 · 열쇠 모양이 맞을 때만 돈다.
- 조작 화면: 연결 → 클라우드 연결 창의 '자료 동기화' 체크. 상태(맞춤 · 맞추는 중 · 끊김 · 멈춤), 올림/받음/충돌 사본/파일 수, 그림·영상 저장소 상태를 보인다.
- 끄면 아무것도 보내지 않고, 출력 자료도 1단계와 똑같다(시험함).

## 2. 무엇을 어떤 모양으로

| 설치판 | 클라우드 kind / id | payload |
|---|---|---|
| `Cuesheets` 줄 (휴지통 빼고) | `cue` / 큐시트 id | `{id, name, serviceDate, startTime, items[], memo, pinned, template}` — 설치판 `Cue` 그대로 |
| `Songs` 줄 | `song` / 곡 id | `get_song` 모양에서 `updatedAt` 뺌: `{id, title, lyrics, credit, tags, arrangement, arrangements[], key, meter, bpm}` |
| 설정 `templates[]` | `template` / 템플릿 id | 템플릿 객체 그대로 (기본 템플릿 `worship` 등 포함) |
| 설정 `customThemes[]` | `theme` / 테마 id | 그대로 `{id, name, desc, slots}` |
| 설정 중 교회 공통 칸 | `settings` / `church` | `CHURCH_KEYS` 만: overlays(켜짐 `on` 뺌) · macros · schedule · stagePresets · messageTemplates · people · scenes · sources · outputScenes · typeScenes · sceneTransition · outputTransitions · split · hymnBackground · nameTagSeconds · logoScreenImage · songSearchUrl |

- **올리지 않는 설정**(기기마다 다름 · 비밀): 포트 · 모니터 · 출력 창 · OBS(비밀번호) · 리모컨 PIN · 내부망 · 장비 · 카메라 · 폴더들 · 창 배치 · 화면 언어 · 단축키 · AI 키 · 클라우드 열쇠 · syncDir · 통계 · 업데이트. 모르는 칸이 생겨도 올라가지 않게 '허락 목록' 으로 골랐다. `activeTemplates`(지금 쓰는 템플릿)도 빼었다 — 웹에서 바꾸면 예배 중 이 PC 의 송출 화면이 바뀌므로.
- 찬양 id 는 설치판 규칙(영문 · 숫자 4~40자)이어야 받는다. 3단계 웹 화면이 곡을 만들 때 이 규칙을 지켜야 한다(아니면 이 PC 는 그 곡을 건너뛰고 지우지도 않음).
- 다른 kind(overlay · macro · usage …)는 받아도 건너뛴다.

## 3. 흐름

1. 한 바퀴(30초마다, 화면에서 고치면 3초 뒤): ① 앞서 답을 못 받은 올리기(outbox)를 같은 mutationId 로 다시 → ② `GET /api/v1/sync?after=<cursor>` 를 `more` 가 없을 때까지 → ③ 설치판 전체를 지문(sha256, 칸 차례 무관)으로 견줘 바뀐 것만 `POST /api/v1/sync` (20개 · 3 MiB 묶음, 설정 → 템플릿 · 테마 → 찬양 → 큐시트 → 지우기 차례).
2. **처음 한 번 전체 올리기**: 기록이 없으면 받기(after=0) 뒤 전체가 '새 것' 이라 다 올라간다(큰 묶음은 '올리는 중 120/950').
3. 기록: `data/cloudsync/state.json` — 교회 · 주소 · cursor · 문서마다 `{rev, hash, deleted}` · outbox · 파일(sha256 · 자산 id) · 가림표. 교회나 주소가 바뀌면 옛 기록은 `state-<교회>-<시각>.json` 으로 옆에 두고 처음부터(다른 교회 자료와 섞이지 않게).
4. mutationId = `pc<기기>-<시각>-<번호>`, **보내기 전에 저장**. 답을 잃으면 다음 바퀴에 그대로 다시 → 서버가 `duplicate` (시험: 두 번 들어가지 않음).
5. 내가 올린 것이 받기에 다시 오면 판 번호로 알아보고 건너뛴다(메아리 없음). 받은 것을 설치판에 넣은 뒤의 지문을 적어 두어 되돌려 올리지 않는다.
6. 끊김: 네트워크 오류는 5 → 10 → … 300초 간격으로 다시. 열쇠가 틀리면(401/403) 설정이 바뀔 때까지 멈춤. 자료 길이 없는 클라우드(404)는 10분마다. 조작 화면 · 로컬 출력 · 리모컨은 그대로. 코어 잠금은 설치판 자료를 읽고 쓸 때만 잠깐 잡는다(네트워크 중에는 안 잡음).

## 4. 충돌 · 지우기 — 덮어쓰지 않는다

| 경우 | 설치판에서 |
|---|---|
| 클라우드에서만 고침 | 받아 넣음 |
| 양쪽에서 고침 (받기에서 · 올리기 409 에서 똑같이) | **원래 자리 = 클라우드 판**, 이 PC 판은 새 id 의 `○○ (충돌 사본 HH:MM)` 으로 남기고 → 다음 바퀴에 사본도 올라감(웹에서도 둘 다 보임). 알림 한 줄. 교회 설정은 사본을 둘 자리가 없어 이 PC 판을 `data/cloudsync/conflicts/settings-<시각>.json` 파일로 |
| 같은 id · 같은 내용 (1.x 자료를 복사한 두 PC) | 판 번호만 맞춤, 사본 없음 (시험함) |
| 클라우드에서 지움 | 큐시트 → **휴지통**(되살릴 수 있음). 찬양 · 템플릿 · 테마 → `data/cloudsync/removed/<종류>-<id>-<시각>.json` 사본을 남기고 지움 |
| 클라우드에서 지웠는데 이 PC 에서 고치던 것 · 쓰는 중인 템플릿(activeTemplates · 테마 칸) · 기본 템플릿 · 교회 설정 | **지우지 않고** 다음 올리기에서 되살림(묘비 판으로 PUT). 알림 한 줄 |
| 이 PC 에서 지움(휴지통 포함) | 클라우드도 지움(묘비 — 서버에서 되살릴 수 있음) |
| 이 PC 에서 지웠는데 클라우드에서 고침 | 클라우드 판으로 되살림 |
| 사본을 못 만듦 | 덮어쓰지 않고 다음 바퀴에 다시 |

- 서버가 거절한 본문(`invalid`) · 1 MiB 넘는 문서는 그 지문을 적어 두고 바뀔 때까지 다시 보내지 않는다(로그에 남김).

## 5. 파일 주소 — PC 경로가 클라우드에 남지 않게

설치판 자료 안 '이 PC 의 파일' 은 `/lib/file?p=<인코딩한 경로>` · 절대 경로(`C:\` · `C:/` · `\\서버\` · `/Users/` · `/Volumes/`) · `file:///…` · `/media/<이름>`(자료 폴더 media). 긴 글 안에 낀 `/lib/file?p=…`(CSS `url(…)`)도 찾는다(이름의 짝 맞는 괄호 `배경 (1).png` 는 안 자름).

**문서(D1, 오래 남음)** — `to_cloud` / `from_cloud`:
- 파일 sha256 → 알던 것이면 그 id, 아니면 `GET /api/v1/assets?sha256=` → 없으면 `POST /api/v1/assets`(90 MB 이하) · 나눠 올리기(넘으면, 서버 partSize) → `/api/v1/assets/{id}?e=.png` (끝의 확장자는 `render.js isVideo` 가 주소 끝으로 영상을 가리기 때문). 같은 내용은 한 번만 올린다.
- 올리지 못한 것(없는 파일 · 저장소가 받지 않는 종류 pptx/pps · 크기 한도 · 저장소 없음 · 507) → `wp-local:<24자 표>` (소금 넣은 sha256 — 경로를 짐작 못 함). 저장소가 생기면 10분 뒤 그 문서를 다시 올려 자산 주소로 채운다.
- 받을 때: 자산 id → 이 PC 의 원래 주소(파일이 아직 있으면), 모르는 자산(웹에서 올린 그림)은 받아서 `media/cloud-<sha16>.<확장자>` → `/media/…`. 가림표 → 원래 주소.
- 받는 종류 · 크기는 2C 표(assets-api.md 2절)대로 미리 거른다. 파일 하나가 4xx 면 그 파일만 '안 받음' 으로 적고 다른 파일은 계속. 507 이면 6시간(그 예배 동안), 저장소 없음 · 열쇠 30분, 네트워크 5분 쉰다.
- `/hymn/…` · `/hymnal/score/…`(찬송가 · 악보)는 올리지 않는다 (assets-api.md 5절의 5 — 사관님이 정하실 것).

**출력 자료(중계실 메모리, render · 리모컨 상태)** — `for_output` (`cloud.rs collect` 에서):
- 올린 파일 → `/api/v1/assets/{id}?fallback=<1단계 중계 주소>` (클라우드에서 없어지면 Worker 가 302 로 중계).
- 아직 안 올린 파일 → `/lib/file?t=<표>.<확장자>` — **경로 대신 표**. 중계실이 설치판에 물으면 `cloud.rs` 가 `relay_request` 로 표 → 경로로 되돌려 로컬 서버에서 읽는다. 그 파일은 올리기 줄에 들어가고, 올라가면 `Ev::Live` 로 다시 보낸다 → 다음 render 부터 자산 주소.
- `/media/<이름>` 은 경로가 아니라 1단계 중계 그대로(올라간 뒤엔 자산 주소).
- 영상 열쇠 `video.key`(= '주소#시각', 경로가 들어 있음)는 `vk-<표>` 로 가리고, 출력 화면이 `videoMeta` · `videoEnded` 로 돌려보내면 `relay_command` 로 되돌린다(영상 길이 · 끝나면 넘기기가 그대로 됨).
- 동기화가 꺼져 있으면 한 겹이 아무것도 바꾸지 않는다(1단계와 같음).

## 7. 확인 못 한 것

- 실제 Cloudflare(원격 D1 · R2) 에 대고는 돌리지 않았다(이 작업은 로컬만).
- 90 MB 넘는 영상의 나눠 올리기는 2C 계약대로 짰지만 끝에서 끝으로는 안 돌렸다. 끊긴 나눠 올리기를 이어 올리기(`GET /uploads/{id}` 의 `done`)는 하지 않고, 실패하면 그만두고(DELETE) 다음 바퀴에 처음부터 한다.
- 조작 화면의 '자료 동기화' 구획은 빌드 · 기존 시험만 했고 캡처로 보지 않았다.
- 실제 설치판(`wp-app`)을 켜 둔 채 30초 바퀴를 오래 돌린 시험은 없다(엔진은 같은 코드를 시험에서 직접 돌림).
- `reset:true`(변경 기록을 줄인 서버)는 서버가 아직 늘 false 라 처리하지 않았다 — 생기면 목록(`include=payload`)부터 다시 받게 할 것.

## 8. 다른 단계가 알 것

**6단계 (오프라인 · `web-offline`)**
- 같은 D1 문서를 설치판도 고친다. 설치판은 '클라우드 판이 원래 자리, 늦게 온 쪽이 사본' 규칙이다 — 웹 쪽도 같은 규칙이면 두 곳의 결과가 같다(사본 이름 `… (충돌 사본 HH:MM)`).
- 설치판이 만든 문서의 파일 주소는 `/api/v1/assets/{id}?e=.확장자` 또는 `wp-local:<표>`(이 PC 에만 있는 파일 — 웹에서는 '설치판에만 있는 파일' 로 보이면 됨, 주소를 바꾸지 말 것: 설치판이 다시 받을 때 원래 경로로 되돌린다).
- 설치판은 30초마다 묻는다(바뀐 것이 없으면 행 읽기 2~3개).

**3단계 (웹 조작 화면 · `web-egui`)**
- 문서 모양은 2절 표 그대로. 큐시트 `items[]` 는 설치판 순서 모양 그대로 둔다(모르는 칸도 지우지 말 것).
- 새 찬양 id 는 영문 · 숫자 4~40자 (설치판 `short_id("s")` 꼴, 예 `s` + base36). 큐시트 id 는 문서 id 규칙이면 된다.
- 그림을 올려 넣을 때 주소는 `/api/v1/assets/{id}?e=.png` 꼴로(끝의 확장자 — `render.js isVideo`). 설치판은 그것을 받아 `media/cloud-…` 로 내려받는다.
- 교회 설정 문서(`settings/church`)는 허락 목록의 칸만 쓴다. 다른 칸을 넣어도 설치판은 읽지 않는다.

## 9. 사관님이 정하실 것

1. **교회 공통 설정의 범위** — 지금 허락 목록(2절). 단축키 · 출력 설정 · '지금 쓰는 템플릿' 까지 PC 사이에 맞출지.
2. **찬송가 · PPT 파일** — PowerPoint(pps · pptx)는 2C 저장소가 받지 않아 이 PC 에만 남는다(웹에서는 그 순서가 비어 보임). 5단계 변환 전까지 이대로 둘지.
3. **처음 켤 때 두 PC 자료가 다르면** — 먼저 켠 PC 의 자료가 클라우드 판이 되고, 나중 PC 의 다른 것은 '충돌 사본' 으로 남는다. 교회 설정은 나중 PC 것이 파일로만 남고 클라우드 판으로 바뀐다. 처음에는 한 PC 만 켜고 나머지는 그 뒤에 켜기를 권함.
