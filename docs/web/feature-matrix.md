# 설치판 기능 → 웹판 대조표

기준: `origin/rust` 951f548 (2026-11-28, 메뉴 막대 안 A). 메뉴는 `crates/wp-app/src/menubar.rs menus()`, 설정은 `settings_items.rs ITEMS`, 판단은 해당 `wp-core` 모듈의 코드를 읽고 했다.
빠진 항목을 찾는 데는 `node cloud/scripts/inventory.mjs` (메뉴 · 설정 id 를 뽑아 이 표와 맞춰 봄)를 쓴다. **분류와 까닭은 사람이 코드를 보고 쓴 것**이고, 스크립트가 정하지 않는다.

- **그대로 됨**: 지금 코드(웹 페이지 · 자료 모양 · 순수 로직)를 거의 그대로 웹에서 쓸 수 있다. 해당 단계의 웹 화면이 이미 있다는 뜻은 아니다.
- **방식이 달라짐**: 같은 일을 하지만 저장소 · 파일 · 운영체제 · 네트워크 경계가 바뀐다. 어떻게 바뀌는지 적었다.
- **안 됨**: 일반 브라우저로는 못 한다. 까닭과 대안을 적었다.
- 단계 = 웹 로드맵 (1 출력·리모컨 클라우드 · 2 자료 클라우드 · 3 웹 조작 화면 · 4 소스·카메라 · 5 AI·변환 · 6 오프라인). 설치판 `docs/roadmap-sources.md` 의 단계 번호와 다르다.

## 먼저 바로잡을 점 (사관님께 어림으로 말씀드린 것과 코드의 차이)

| 어림 | 코드에서 확인한 것 |
|---|---|
| NDI · 가상 카메라는 웹에서 안 됨 | 맞지만, **지금 설치판에도 NDI 송신 · 가상 카메라 출력이 없다** (`crates/` 전체에 NDI 코드 없음). 방송은 OBS 브라우저 소스로 한다. 그래서 '웹으로 옮기며 잃는 기능' 이 아니다. 웹판도 OBS 브라우저 소스 주소(클라우드 주소)로 같은 일을 한다. |
| PPT · HWP 변환은 새 방식 필요 | 반만 맞다. **`.pptx` 는 이미 PowerPoint 없이 직접 읽고 그린다** (`pptx/` 파서 → SVG → resvg PNG, 순수 Rust). PowerPoint(COM)는 `.ppt/.pps` 옛 형식과 '픽셀 그대로' 경로에서만 쓴다. **HWP/HWPX/DOCX 글 꺼내기도 순수 Rust** (`bulletin.rs`: CFB · zip · XML). 둘 다 WASM 으로 브라우저에서 돌리거나, 설치판이 그림으로 만들어 R2 에 올리는 길이 있다. 새로 필요한 것은 옛 `.ppt` 의 '픽셀 그대로'(PowerPoint 필요)와 **PDF**(`pdf.rs` 는 Windows.Data.Pdf · 맥 PDFKit — 브라우저에서는 pdf.js 로 바꿔야 함)뿐이다. |
| 음성 인식은 클라우드 AI | 지금은 **PC 안 whisper.cpp** 다 (`stt.rs`, 음성은 PC 밖으로 안 나감). 웹에서는 ① 같은 PC 의 설치판이 듣고 결과 글만 보냄 ② 브라우저 안 WASM whisper ③ 동의를 받은 클라우드 인식 — 셋 중 고른다. 클라우드만 길이 아니다. 지킬 선(결과는 '다음' 칸까지만, 송출 금지)은 그대로. |
| 성경 DB 를 올리면 됨 | `bible.db` 는 성경만이 아니라 큐시트 · 찬양 · 템플릿 · 기록이 다 든 자료 DB 다. 번역본은 저작권이 있어 **교회마다 허락된 번역본만, 로그인 뒤에만** 둔다. D1 무료 DB 한 개는 500 MB 까지라 번역본을 다 넣지 않는다. |
| 출력 화면은 이미 웹이라 바로 됨 | 맞다 (1단계에서 확인). 다만 **글꼴**: 조작 화면의 슬라이드 나누기(`measure.rs`)는 맑은 고딕 기준이고, 다른 PC(맥 · 휴대폰)의 브라우저에는 맑은 고딕 · 구세군체가 없을 수 있어 줄바꿈이 달라질 수 있다 → 2단계에서 웹 글꼴(R2)로 맞춘다. |
