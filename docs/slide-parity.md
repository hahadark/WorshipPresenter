# 조작 화면 슬라이드 그림 = 웹 출력 (2026-11-15)

사용자 보고: "지금 실제 출력 화면과 편집기에서 보이는 화면이 달라". 예: 레드 쉴드 · 예배당 템플릿을 9칸 '아래·오른쪽'으로 두면
실제 예배당 화면은 14번 '광고'(공지, 본문 없음 → 제목 슬라이드)를 오른쪽 아래에 그리는데, 조작 화면 LIVE 는 가운데에 그렸다.

조작 화면의 미리보기·LIVE·썸네일·슬라이드 편집기·템플릿 편집기 그림은 모두 `crates/wp-app/src/paint.rs` 의 `paint_slide` 하나로 그린다.
이제 이 함수는 웹 출력(`web/shared/render.js` · `render.css` · `web/output/index.html`)의 규칙을 그대로 옮겨 그린다.

## 구조

| 파일 | 내용 |
|---|---|
| `crates/wp-app/src/slide_layout.rs` | 자리 계산 순수 함수 + 단위 시험: 글 영역(contentRect), 9칸 배치(flex justify + text-align), 로고 자리(높이=크기, 폭=그림 비율), 고정 장절, 꼬리말, 로고 화면, 내어쓰기 번호 칸, lyricsOnly, 위첨자·작은 글자 기준선 |
| `crates/wp-app/src/css_bg.rs` | CSS `linear-gradient`·`radial-gradient` 여러 겹을 브라우저 규칙(멈춤 위치·farthest-corner·곱한 알파)으로 계산 + 단위 시험 → 텍스처 |
| `crates/wp-app/src/paint.rs` | 배경층(배경·흐림·로고) → 본문층(종류별) → 로고 화면. 글 덩어리는 `.bc-block` 처럼 조각(장절·본문 문단·소제목·병행 번역·번역본)을 쌓는다 |
| `crates/wp-app/src/parity_shot.rs` | 점검 인자 `--parity` |
| `tools/parity/` | 경우 목록(`cases.js`), 점검 앱 실행(`run.ps1`), 웹 쪽 그리기(`web-render.js`) |

## 크기 맞춤·줄바꿈

웹 `fit()` 과 같은 순서(설정 크기 → 넘치면 최소 크기 → 정수 이분 탐색)로, **템플릿 해상도(px)** 에서 잰다.
줄바꿈은 egui 자동 줄바꿈 대신 CSS 규칙으로 직접 정한다: `word-break: keep-all`(빈칸 뒤에서만), 줄 끝 빈칸은 폭에 넣지 않음,
끊을 데가 없으면 글자 사이(`overflow-wrap: anywhere`). 정한 자리는 작은 화면(썸네일·LIVE)에도 그대로 써서, 화면 크기와 상관없이 줄이 같다.
줄 높이 합은 CSS 처럼 `줄 수 × line-height` (egui 의 픽셀 반올림 합을 쓰지 않음).

## 비교 방법

1. 점검 자료를 작업트리 `tmp\data` 로 복사 (사용자 자료 `%APPDATA%` 는 쓰지 않는다).
2. `node tools\parity\cases.js tmp\cases.json` → `pwsh tools\parity\run.ps1 -Cases tmp\cases.json -Out tmp\pout`
   - 앱이 1280×720 창에 경우마다 슬라이드 그림만 그려 `rust-<이름>.png`, 웹용 `resolved.json`(템플릿·슬라이드), 고른 글자 크기 `fit.txt`, `port.txt` 를 남긴다.
   - `--parity-hold`: `close.txt` 를 만들 때까지 서버를 띄워 둔다.
3. 브라우저(1920×1080)로 `http://127.0.0.1:<port>/outputs/main` 을 열고 `web-render.js` 의 `parityRender(경우)` 로 그려 찍는다 → 나란히 비교.
   - 웹 fit 크기(반환값)와 `fit.txt` 가 같아야 한다.

## 남은 차이 (일부러 그대로 둔 것)

- 영상 슬라이드·카메라 슬라이드·영상/카메라 배경: 조작 화면은 검은 바탕 + 이름표 (실제 화면은 재생). 조작 화면에서 영상을 재생하지 않는다.
- 글꼴: 템플릿 첫 글꼴이 맑은 고딕이 아니면 그 글꼴을 찾아 쓰고, 못 찾으면 맑은 고딕. 굵기는 400/700 두 단계(브라우저는 글꼴에 따라 500·600 등도).
- 글자 그림자 흐림은 여러 번 겹쳐 그린 근사, `-webkit-text-stroke` 는 12방향 근사. 기울임(italic) 서식은 그리지 않는다.
- `{크기:150}` 처럼 큰 글자가 섞인 줄의 기준선은 근사 (작은 글자는 웹처럼 본문 밑줄에 맞춤).
- 그림 우상단(pip)의 둥근 모서리는 그리지 않음(그림자만).
- 로고 화면(F 로고)의 그림: 설정 `logoScreenImage` 대신 템플릿 로고(없으면 구세군 방패)를 쓴다.
